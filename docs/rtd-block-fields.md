# RTD Block 欄位說明

## Rule 的本質

一條 Rule 就是一條**資料處理流程**，由多個 Block 串接而成，每個 Block 只做一件事。

**主線（MAIN）** 是儲存核心資料與欄位的地方。從起點撈資料，經過一連串的加工，最終輸出到 DispatchScreen。

**副線（SUB）** 負責在資料流程中補充額外資訊。副線本身不留資料，最後一定會接上一個 Index Block 串回主線。

**Index** 是主副線的接合點。它的 PREBLOCK 有固定角色：

- `PREBLOCK[0]`：要**留下資料**的那一方（通常是主線）
- `PREBLOCK[1]`：要**串進來**的那一方（副線）

所有資料來源類型的 Block（例如 Database、Repository）**不可能有 PREBLOCK**，它們一定是所在分支的起點。

不管 Rule 的目的是什麼，這個結構都不變。

### 怎麼串資料

每個 Block 透過 `PREBLOCK` 指定它的上游。資料從上游 Block 流到下游 Block，每一層可以讀取前面所有 Block 已經產出的欄位。Function Block 的 KEY 就是新增的欄位名稱，後續的 Block 都可以直接用這個名稱引用它。

### 怎麼判斷

判斷邏輯寫在 VALUE 欄位，語法是 APF 表達式：

```
IF <欄位> <運算子> <值> THEN <結果> ELSE IF ... ELSE <結果>
```

條件和結果都可以引用前面 Block 產出的欄位。結果也可以是 `[$LOG_NAME$]`，代表觸發一個 Log 事件而不是回傳值。

---

## 共用欄位

| 欄位 | 說明 |
|------|------|
| `BLOCK_NAME` | Block 唯一識別名稱，Function Block 帶 `[idx]` 後綴（例如 `FUNC[0]`） |
| `BLOCK_TYPE` | Block 類型，決定欄位用法（見下方各節） |
| `BLOCK_GROUP` | `MAIN` = 主線；其他 group name = 副線（各自撈資料後透過 Index 串回主線） |
| `BLOCK_SEQ` | Rule 內執行順序編號 |
| `PREBLOCK` | 前置 Block（逗號分隔最多 2 個）。第一個 = 主線來源；第二個 = 副線來源 |
| `POSX / POSY` | Canvas 畫布座標（純佈局） |
| `CLAIM_TIME` | 最後更新時間 |

---

## 副線串接邏輯

```
主線：  DB(MAIN) → FUNC(MAIN) → ... → INDEX(MAIN) → DS(MAIN)
副線：  DB(G1)   → FUNC(G1)   ──────────────────────┘
        DB(G2)   → FUNC(G2)   ──────────────────────┘
```

Canvas 上兩端都是 MAIN 的連線顯示為藍色粗實線；其他為灰色細線。

---

## APF 表達式語法（VALUE 欄位）

```
IF <var> <op> <val> THEN <result> ELSE IF ... ELSE <result>
```

- 條件：`field op value`（例如 `HOLD_COUNT > 10`、`LOT_STATUS == "HOLD"`）
- 結果：字串 `"PASS"`、數字 `10`、欄位名稱、或 Log 引用 `[$LOG_NAME$]`
- `[$LOG_NAME$]` 只能出現在 THEN 位置
